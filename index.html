PROJECT 01 / CASE STUDY

공모온 (Gongmo-On)

AI 아이디어 분석 · 공모전 추천 웹 서비스

“나를 모른 채 공모전을 준비한다”는 문제에서 출발했습니다. 흩어진 공모전 정보와 객관적 피드백의 부재를 해결하기 위해, 성향 검사부터 아이디어 분석·추천, 연습 노트, 대시보드까지 개인화된 응모 준비 경험을 설계하고 개발했습니다.

351건실제 공모전 DB 자동 수집
42%AI 분석 응답 시간 단축
61개프론트·백엔드 자동 테스트
12일첫 커밋 기준 개발 기간(약)

01. 문제 정의

  • 공모전 정보가 여러 사이트에 흩어져 적합한 공모전을 찾기 어렵다.
  • 내 아이디어의 강점과 약점을 객관적으로 평가받기 어렵다.
  • 제안서와 예상 질문 등 출품 직전 준비를 도와줄 도구가 부족하다.

02. UX 접근과 핵심 기능

개인화의 출발점

20문항·7유형 성향 검사와 편향 방지 문항 배분을 설계해 사용자 특성을 먼저 파악하도록 했습니다.

아이디어 분석 및 추천

아이디어 적합도와 개선점을 AI가 분석하고, 실제 데이터베이스에 존재하는 공모전 중 상위 4건을 추천합니다.

응모 준비 여정

유형 검사 → AI 분석·추천 → 연습 노트 → 대시보드를 하나의 사용자 흐름으로 연결했습니다.

데이터 연속성

localStorage 캐시와 서버 백업을 결합해 여러 기기에서도 데이터를 복원하도록 설계했습니다.

03. 담당 역할과 구현 범위

1인 풀스택 전담 — 기획, UX 설계, 프론트엔드, 백엔드, 테스트, 발표 전 과정 수행.

기획 · UX

문제 정의, 사용자 여정, 20문항·7유형 검사 및 편향 방지 배분 설계.

프론트엔드

React 19 · TypeScript · Vite 기반 9개 화면 SPA. History API 직접 라우팅 및 하이브리드 동기화 구현.

백엔드 · 데이터

Python 3.14 · FastAPI REST API 14종, PostgreSQL 17(Docker) 8개 테이블, LLM 응답 검증. 위비티·콘테스트코리아 6시간 주기 수집기 구현.

인프라 · 검증

Render 배포 준비(Dockerfile · render.yaml), 프론트 26개와 백엔드 35개 자동 테스트 구축.

04. 주요 문제 해결

AI 응답 지연

본문·점수 요청을 병렬 분리하고 스트리밍과 간결한 응답 규칙을 적용해 28.4초에서 16~17초로 단축했습니다.

AI 환각 방지

실제 공모전 정보는 DB만 사용하고 AI는 분석 문장만 생성하도록 분리했습니다. 서버가 제공하지 않은 공모전 ID는 제거합니다.

기기 변경 시 데이터 유실

로그인 시 서버 백업 복원을 우선하고 복원 전 푸시를 막는 게이트(canPushRef)를 구현했습니다.

동시 쓰기 및 데이터 무결성

JSON 파일 저장소를 PostgreSQL로 전환하고 FK·트랜잭션·UNIQUE 제약을 적용했습니다. 기존 계정·해시·API 계약도 유지했습니다.

05. 결과

실제 공모전 351건과 유사 사례·수상작 아카이브 54건을 구축하고 6시간마다 갱신하도록 구성했습니다. AI 분석 응답 시간을 약 42% 줄였으며, 61개 자동 테스트로 주요 동작을 검증했습니다.

개발 규모: 약 12일 · 9개 화면 · REST API 14종 · DB 8개 테이블. 성과 수치는 프로젝트 개발·테스트 기준입니다.
